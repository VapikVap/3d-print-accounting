# Техническое описание

```text
УЧЁТ 3D-ПЕЧАТИ
==============

Локальное приложение: следит за принтерами и розетками, само заводит задания печати,
считает расход нити, электроэнергию и себестоимость, выгружает всё в Excel.

ЗАПУСК
  Первый раз: start.bat — создаёт .venv, ставит requirements.txt, кладёт ярлык
  «Учёт 3D-печати» на рабочий стол и в меню «Пуск» и открывает окно приложения.
  Дальше — просто ярлык. Нужен Python 3.10+ и WebView2 (в Windows 11 уже есть).

  Приложение — отдельное окно (pywebview/WebView2), браузер не нужен.
  Крестик прячет окно в трей: учёт печати продолжается в фоне. Полный выход —
  правой кнопкой по значку в трее → «Выход». Повторный запуск ярлыка показывает
  уже открытое окно, вторая копия не создаётся.
  Внутри работает локальный сервер на 127.0.0.1:8765 — снаружи он недоступен,
  запросы от чужих сайтов в браузере отклоняются (проверка Host/Origin).

  Ярлыки заново: .venv\Scripts\python.exe tools\create_shortcuts.py
  Убрать ярлыки: .venv\Scripts\python.exe tools\create_shortcuts.py --remove
  Без окна (для отладки): .venv\Scripts\python.exe app\server.py и браузер на 127.0.0.1:8765
  Ошибки окна пишутся в data\app.log.

ДАННЫЕ
  data/print.db          — база SQLite (принтеры, розетки, катушки, задания, журнал).
  data/backup/           — резервные копии. Делаются автоматически перед каждой миграцией
                           схемы и вручную кнопкой «Резервная копия базы» в «Настройках».

СЕКРЕТЫ
  Код доступа Bambu (access_code), local key Tuya (plug_key) и токен Яндекса (token)
  хранятся только в локальной базе. В API они не возвращаются (только флаг «сохранён»),
  в журнале и сырых ответах заменяются на ***, в Excel не выгружаются.
  При изменении устройства пустое поле секрета = оставить прежнее значение.

ФАЙЛЫ
  app/db.py        схема, миграции, резервные копии, вычищение секретов
  app/desktop.py   окно приложения, значок в трее, одна копия
  app/server.py    HTTP API и раздача интерфейса
  app/logic.py     граммы из мм, энергия, себестоимость
  app/printers.py  опрос принтеров и розеток (фоновый поток раз в 5 с), ведение заданий
  app/bambu.py     Bambu Lab: MQTT/TLS 8883, пользователь bblp, пароль = код доступа,
                   топик device/{serial}/report
  app/bambu_ftp.py файл задания с принтера Bambu по FTPS (порт 990)
  app/parts.py     пластики задания, привязка катушек к слотам AMS
  app/discovery.py автопоиск принтеров Bambu в сети (SSDP, UDP 2021/1990)
  app/bambu_models.py коды моделей (C12 = P1S …) из Bambu Studio
  app/autostart.py запуск вместе с Windows (HKCU\...\Run)
  app/slicer.py    разбор .gcode и .gcode.3mf из папки слайсера
  app/bambu_studio.py  поиск и запуск Bambu Studio, профили филамента, недавние папки
  app/export.py    Excel
  app/static/index.html  интерфейс
  tools/mock_moonraker.py  эмулятор Moonraker (7125) и розеток Shelly/Tasmota (7126)
  tests/           проверки (run_tests.bat); работают на временной базе

BAMBU STUDIO
  Программа ищется сама: папка «Bambu Studio» в проекте, затем Program Files.
  Другой путь — вкладка «Bambu Studio» → «Другая программа…».
  Что связано:
    - папка нарезки: сохраняйте в неё .gcode.3mf (Файл → Экспорт → Экспорт нарезанного
      файла пластины) — оттуда берётся план расхода и времени; есть подсказки из
      недавних папок Bambu Studio;
    - кнопка «Открыть» у файлов нарезки и «В Bambu Studio» у заданий;
    - новая катушка: параметры (материал, плотность, диаметр) из профилей Bambu Studio,
      свои профили — вместе с ценой. Цены системных профилей не берутся (они условные).
  Из %APPDATA%\BambuStudio\BambuStudio.conf читаются только пути и версия — коды
  доступа и данные входа, которые там хранятся, приложение не читает.

КАК СЧИТАЕТСЯ
  Нить:
    Moonraker — print_stats.filament_used (мм) с принтера; в граммы по соотношению г/мм
                из метаданных файла, иначе по диаметру и плотности катушки.
    Bambu     — план из файла нарезки: «завершено» = весь план,
                «ошибка/прервано» = план × прогресс (mc_percent).
                Файл берётся С ПРИНТЕРА: при начале печати приложение скачивает
                .gcode.3mf по FTPS (порт 990, bblp / код доступа) из корня SD,
                /cache или /model и берёт нужную пластину (gcode_file → plate_N).
                Копии — в data\printer_files (последние 60). Если файла на принтере
                нет — ищется в папке нарезки по имени. НЕ ПРОВЕРЕНО на реальном P1S:
                «Проверить связь» покажет, видны ли файлы по FTPS и в каких папках.
  Энергия:
    счётчик розетки (Shelly, Tasmota, Tuya dps энергии) → разница показаний;
    только мощность (Яндекс, или если dps энергии пуст) → интегрирование мощности;
    без розетки → средняя мощность принтера × время (оценка).
  Несколько пластиков в детали (AMS):
    из файла нарезки берутся все пластики пластины (тип, цвет, граммы). Катушка для
    каждого: 1) слот AMS с таким же типом и близким цветом, если к слоту привязана
    ваша катушка (Обзор → карточка принтера → «Заряжено в принтер»); 2) ваша катушка
    того же типа с ближайшим цветом; 3) иначе «нет катушки» (стоимость 0 — видно в
    задании). Выбор можно поправить в задании — ручной выбор не перезаписывается.
    Стоимость и списание — по каждой катушке отдельно. Excel: лист «Пластики».
  Себестоимость = нить + энергия × тариф + амортизация × часы + работа оператора.
  Цена = себестоимость × (1 + наценка).

КОГДА ПРИЕДЕТ P1S COMBO (с AMS 2 Pro)
  0. В принтере должна стоять microSD-карта: по описанию Bambu Studio P1S не печатает
     по сети без неё (support_print_without_sd = false), файлы задания лежат на ней.
  1. Включите принтер в ту же сеть, что и компьютер (IP лучше закрепить в роутере).
     Приложение само найдёт его по объявлению в сети (как Bambu Studio) и добавит:
     модель, IP, серийный номер, имя. Если Windows спросит разрешение брандмауэра
     для Python — разрешите для частной сети, иначе поиск не увидит принтер.
  2. На «Обзоре» у принтера кнопка «Ввести код доступа» — код с экрана принтера.
     «Проверить связь» покажет: прошивку, тип подачи (A — AMS 2 Pro), FTPS.
  3. «Филамент»: катушки с ценой за кг, типом и цветом. Пластики детали сопоставятся
     с ними сами по типу и цвету; точнее — привязать катушку к слоту AMS на «Обзоре».
  4. Печатайте из Bambu Studio как обычно — задание, пластики и себестоимость появятся сами.
  Если принтер получит новый IP — приложение обновит его само (узнаёт по серийному).
  Не нашёлся — «+ Добавить принтер» вручную; удалённый найденный принтер сам не вернётся
  («Устройства» → «Найдены в сети» → «Добавить»).

  AMS 2 Pro: тип блока приложение спрашивает у принтера (get_version: модуль n3f —
  AMS 2 Pro, n3s — AMS HT, ams — AMS). Влажность (%), температура и остаток сушки
  показываются, если принтер их присылает. Эти поля и коды модулей — по открытым
  разборам протокола, на вашем принтере ещё не проверены.
  Если приложение было закрыто — печать не учтётся, поэтому включите автозапуск
  с Windows: Настройки → Запуск (галочка; приложение само в автозагрузку не прописывается).
  Если открыли посреди печати — время начала оценивается.

ТЕМЫ
  Настройки → Оформление: фиолетовая, светлая, чёрная, графит, как в Windows.

ДЕМО (без принтера)
  .venv\Scripts\python.exe tools\demo.py   → http://127.0.0.1:8766
  Временная база + эмулятор P1S (tools/mock_bambu.py: MQTT по TLS, FTPS, AMS из
  4 слотов, двухцветная деталь). Рабочая база не трогается.

ЭМУЛЯТОР
  .venv\Scripts\python.exe tools\mock_moonraker.py --auto 30
  Затем в приложении: принтер Moonraker, IP 127.0.0.1, порт 7125;
  розетка Shelly Gen2 / Gen1 / Tasmota, адрес 127.0.0.1:7126.

ЧТО НЕ ПРОВЕРЕНО НА РЕАЛЬНОМ ОБОРУДОВАНИИ
  - Moonraker на настоящем K1 Max (порт, filament_used, метаданные, история).
  - Bambu Lab: подключение, формат отчётов, переходы gcode_state.
  - Tuya: номера dps и множители у конкретной модели, версия протокола.
    ВНИМАНИЕ: у многих розеток Tuya dps 17 («add_ele») — прирост энергии с прошлого
    отчёта, а не накопленный счётчик. Если так — очистите поле «dps энергии», и
    энергия будет считаться по мощности.
  - Яндекс: формат ответа и название параметра мощности.
  Кнопка «Проверить связь» показывает сырой ответ устройства — по нему правится разбор
  и добавляется тест в tests/test_plugs.py (класс RealSamplesTest).
```
